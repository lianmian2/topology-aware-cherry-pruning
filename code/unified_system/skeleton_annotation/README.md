# 骨架拓扑标注系统

本系统用于手工标注樱桃树的 2D 骨架拓扑图，输出可直接用于训练模型的标注数据。标注成果作为端到端骨架预测模型的 ground truth，最终目标是将分割图 + 芽点信息直接映射为清洁的树拓扑骨架。

## 设计理念

- **不把 2D 骨架当植物学真值**，而是作为模型学习的工程参考
- **分叉点无需手工标记**：由拓扑自动推导（度 ≥ 3 的节点即为分叉点）
- **标注的是语义分组，不是像素**：主干 1 组 + 每根一级枝条 1 组，按序点选关键点连接成折线
- **训练时**：分叉点严格要求预测，中间弯曲点不硬性要求精度（只需保持枝条形态）

## 操作流程

### 1. 打开图片文件夹

点击 **📁 打开图片文件夹**，选择 `sampled_images/`（或任意图片文件夹）。左侧列表自动加载所有图片，点击即可切换。切换图片时**自动保存**当前标注、**自动加载**已有标注。

### 2. 标注主干

点击 **🌳 主干模式**，在原图上点选主干的各个关键点。程序自动按序连接为红色折线。

- 主干通常从底部根茎开始，沿垂直轴向上，到树冠基部结束
- 对于被条带遮挡的断裂段，直接跨过断裂区点选关键点

### 3. 新建枝条

点击 **🌿 新建枝条（起点必须在主干上）**，主干线段会高亮为青色。在主干上点击起点（自动吸附到主干线段）。

此后可以：
- **在空白处点击** → 添加该枝条的后续弯曲点
- **hover 已有节点** → 青色放大环反馈 → **点击** → 从该节点分叉（点仍在当前枝条组中）

快捷键：`Ctrl + A` 新建枝条

### 4. 完成标注

标注完一棵树的所有枝条后，点击 **💾 手动保存当前标注**（切换图片时也会自动保存）。

### 其他操作

| 操作 | 方式 |
|------|------|
| 撤销上一个点 | 点击按钮 或 `Ctrl + Z` |
| 切换活跃分组 | 左侧分组列表点击 |
| 删除当前组 | 🗑 删除当前组 |
| 缩放 | 鼠标滚轮 |
| 平移 | 右键拖拽 |
| 加载分割 Mask | 🗺 加载分割Mask（可选，绿色叠加显示） |

## 交互语义

### 两个关键规则

1. **新建枝条组 = 从主干分叉**
   - 有几个枝条组 = 主干上有几个分叉点
   - 只能在「新建枝条」时点主干线段

2. **在枝条组中点击已有节点 = 分叉**
   - hover 节点 → 青色环反馈 → 点击分叉
   - 不会创建新组，点追加在当前枝条组内

### 撤销栈

系统维护完整的操作历史，`Ctrl + Z` 撤销整步操作：

- 撤销"加点" → 移除该点；如果枝条组变空 → 自动删除该组，回退 branch_count
- 撤销"新建枝条" → 删除空枝条组，恢复 prior 活跃组和等待状态

### 点到即止，点到即连

- 标注时**不是涂抹像素**，而是点选关键点 → Bresenham 直线连接
- 弯曲的枝条可以点多个中间点来贴合实际形态
- 枝条起点（菱形标记）必然落在已有分组的线段上

## 输出格式

标注数据保存在图片所在目录的 `skeleton_annotations/` 子文件夹中，每个图片生成三个文件：

```
sampled_images/
└── skeleton_annotations/
    ├── tree_012_before_view_01_skeleton.json      ← 结构化数据
    ├── tree_012_before_view_01_skeleton_mask.png   ← 二值骨架图（训练 target）
    └── tree_012_before_view_01_skeleton_overlay.png ← 彩色分组叠加图
```

### JSON 结构

```json
{
  "image_path": "D:/.../tree_012_before_view_01.jpg",
  "image_width": 2048,
  "image_height": 1536,
  "groups": [
    {
      "group_id": "trunk",
      "group_type": "trunk",
      "color_hex": "#FF3232",
      "points": [[800, 1400], [800, 1000], [800, 600]],
      "fork_origin_group": null
    },
    {
      "group_id": "branch_01",
      "group_type": "branch",
      "color_hex": "#32FF32",
      "points": [[800, 1000], [700, 850], [600, 600], [550, 500]],
      "fork_origin_group": "trunk"
    }
  ]
}
```

| 字段 | 说明 |
|------|------|
| `group_id` | 主干为 `"trunk"`，枝条为 `"branch_01"` ~ `"branch_NN"` |
| `group_type` | `"trunk"` 或 `"branch"` |
| `points` | 有序关键点坐标 `[[x, y], ...]` |
| `fork_origin_group` | 该枝条从哪个分组分叉出来（枝条起点落在该分组的线段或节点上） |

### 分叉点的推导方式

不需要在 JSON 中显式存储分叉点。下游解析代码只需：

1. 将所有组的 `points` 合并为图节点
2. 统计每个节点的出现次数（坐标完全相等的点视为同一节点）
3. 度 ≥ 3 的节点 = 分叉点

其中，枝条的 `points[0]` 必定与父分组的某个点重合（因其通过吸附保证），这自然形成分叉结构。

## 抽样数据说明

`sampled_images/` 中的 100 张图片从 `final_data`（165 棵树 × 2 状态 × 6 视角）中随机抽取。

| 维度 | 分布 |
|------|------|
| 视角：正面+背面 (view_01/04) | 70% |
| 视角：侧面 (view_02/03/05/06) | 30% |
| 状态：修剪前 (before) | 80% |
| 状态：修剪后 (after) | 20% |
| 随机种子 | 42（可复现） |

如需重新抽样，运行 `sample_images.py`。
